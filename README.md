 扫码点餐小程序如何支持外卖和堂食双重功能

扫码点餐小程序同时支持堂食与外卖，需在架构、订单流程和履约方式上做区分设计，实现一套系统覆盖两种场景。

一、入口区分

堂食：顾客扫桌码进入，通过 scene 参数解析门店 ID 与桌号，自动绑定桌台，下单后标记“堂食”。

外卖：从首页外卖入口或门店列表进入，需填写收货地址、选择配送时间，系统按距离计算运费与配送范围。

二、订单流程差异

环节	堂食	外卖
下单	绑定桌号，无需地址	填写地址，校验配送范围
支付	先付/后付可选	在线支付
履约	后厨出餐，服务员送餐	骑手接单配送或商家自配
状态	待出餐→已上菜→完成	待接单→配送中→已送达
三、技术实现要点

数据模型：订单表增加 order_type 字段（堂食/外卖），堂食关联 table_id，外卖关联 address_id 与配送信息。

菜品管理：同一菜品可分别设置堂食价与外卖价，或独立上架，避免价格冲突。

后厨打印：按订单类型分单打印，堂食打桌号，外卖打收货信息与骑手单。

配送对接：外卖可对接达达、蜂鸟等聚合配送，或自建骑手端抢单派单。

支付分账：SAAS 平台通过微信支付服务商模式统一收款，按门店与订单类型分账。
